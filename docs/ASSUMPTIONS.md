# Assumptions

Every entry states what is assumed, why it is needed, and how to verify or
override it. Nothing here is a verified fact unless marked VERIFIED.

| ID | Assumption | Why needed | Status | Override |
|---|---|---|---|---|
| A-01 | The DMA/RF sample rate equals the browser's audio sample rate, so no resampling occurs anywhere in the chain. | Resampling would add filter delay and CPU load on a Pi Zero. | ASSUMED | The browser reports its real rate in `hello`; the server starts the sink at that rate. If the browser reports a rate outside 8000-192000 the connection is rejected with an explicit error. |
| A-02 | `librpitx` paces transmission to keep the DMA FIFO 3/4 full, so steady-state sink latency is `0.75 * fifo_samples / sample_rate`. | This is the single largest latency term and the basis of the whole fix. | VERIFIED - `librpitx/src/iqdmasync.cpp`, `SetIQSamples()`. | Not overridable without patching librpitx; see ADR-003. |
| A-03 | The GPIO clock, and therefore the carrier, is enabled in the `iqdmasync` constructor before any IQ sample is written. | Explains the tune tone at key-down. | VERIFIED - `librpitx/src/iqdmasync.cpp:38` (`clkgpio::enableclk(4)`), with upstream's own `FixMe carrier is already there` comment at line 36. | `webtx_iq --ptt-gate`. |
| A-04 | `fifo_samples = 2048` is small enough for low latency and large enough to avoid underruns on a Pi 3 or newer under normal load. | A default has to be chosen. | ASSUMED - not measured on hardware by this work. | `sink.fifo_samples` in the config. `native/README.md` gives per-model recommendations. Underruns are counted and shown in the UI so the operator can tune it empirically. |
| A-05 | A 129-tap Hilbert transformer gives adequate opposite-sideband suppression for voice SSB. | Determines SSB quality versus the 1.34 ms group delay it costs at 48 kHz. | VERIFIED by unit test (measured suppression is asserted in `tests/test_dsp.py`). | `dsp.hilbert_taps` in the config. |
| A-06 | The default SSB audio passband of 300-2700 Hz is appropriate for communications-quality voice. | A default has to be chosen. | ASSUMED | `dsp.ssb_low_hz` / `dsp.ssb_high_hz`. |
| A-07 | The default FM deviation of 2500 Hz corresponds to amateur narrowband FM practice. | A default has to be chosen; deviation is not derivable from the hardware. | ASSUMED - not measured against a deviation meter. | `dsp.fm_deviation_hz`. |
| A-08 | The browser and the Raspberry Pi do not share a clock, so a raw difference between the client timestamp and server time is not a valid one-way latency measurement. | Prevents reporting a meaningless number as latency. | VERIFIED by construction. | The server reports arrival jitter relative to the minimum observed offset, and reports absolute RTT separately via ping/pong. |
| A-09 | `python3-numpy` and `python3-aiohttp` are installable from the Raspberry Pi OS archive on the supported releases. | Determines the installation path in `install.sh`. NumPy specifically has no official PyPI wheel for 32-bit ARMv7, so the apt package is the safer default on older Pi models; pip is only a fallback. | ASSUMED for releases other than Bookworm. | `install.sh` tries apt first, then falls back to `pip3 install --break-system-packages numpy aiohttp pytest`. |
| A-10 | The operator provides the mandatory low-pass or band-pass harmonic filtering required for any transmission from a Raspberry Pi GPIO. | rpitx generates a square wave; harmonics are inherent to the hardware, not to this software. | NOT SOFTWARE-CONTROLLABLE | Documented in `README.md`. There is no software mitigation; the filter is a hardware requirement. |
| A-11 | Only one operator keys the transmitter at a time. | There is one physical transmitter. | ENFORCED in software - the first client to key holds TX; other clients receive an explicit error. | Not configurable. |
| A-12 | `webtx/server.py` requires `aiohttp >= 3.9` (uses `aiohttp.web.AppKey`, added in aiohttp 3.9.0). Ubuntu 22.04's apt-shipped `python3-aiohttp` is 3.8.1, which lacks it and is therefore insufficient. | Confirmed on real hardware: the server crashed at startup with `AttributeError: module 'aiohttp.web' has no attribute 'AppKey'` when apt's 3.8.1 was installed. | VERIFIED - Raspberry Pi 2, Ubuntu 22.04, 2026-09-02. | `install.sh` now checks for `aiohttp.web.AppKey` (not just that `aiohttp` imports) and pip-installs/upgrades to `aiohttp>=3.9` when it is missing. |
